# janus-public

야누스의 **공개 발행 표면**. Cloudflare Pages 가 이 저장소의 `public/` 을 읽어 서빙한다.

> ⚠ **이 저장소는 public 이다.** 여기 올라간 것은 커밋을 되돌려도 사라지지 않는다 —
> git 이력·GitHub 캐시·포크에 남는다. 그래서 이 README 의 절반은 "무엇을 넣는가"가 아니라
> **"무엇을 절대 넣지 않는가"** 다.

## 이 저장소의 성격 — 콘텐츠의 출처가 아니다

정본은 전부 `janus-platform`(private)에 있다. 여기는 그 **사본을 놓는 자리**다.

| | 정본 | 여기 |
|---|---|---|
| 마케팅 랜딩·서비스 소개 | `janus-platform/marketing/src` | `public/*.html` (생성물 사본) |
| 무료 배치표 | `janus-platform` 티어 빌드(`dist-tier/free`) | `public/baechi/` |

**여기서 직접 고치지 않는다.** 고치면 두 벌이 되고, 두 벌이 되면 어느 쪽이 맞는지 아무도 모르게 된다.
반입은 스크립트로만:

```bash
scripts/stage-from-platform.sh --platform ../10_platform/janus-platform
```

## 절대 넣지 않는 것

- **저작권 데이터** — 어디가·esteacher·고속 유래 원천과 그 파생 수치. private 저장소에도 못 넣는 것이 여기 들어올 리 없다.
- **상위 티어 산출물** — `dist-tier/{member,paid,consultant}`. 공개는 **무료판만**이다(접합계약 C4).
- **원천 데이터 파일** — `.xlsx`·`.csv`·`.sql`·`.db` 류.
- **시크릿** — `.env`·키·토큰.

`.gitignore` 가 1차, `scripts/check-public-safe.sh` 가 2차 방어선이다.

## 가드

```bash
scripts/check-public-safe.sh    # 발행 전 검사 (pre-commit·CI 가 같은 것을 부른다)
scripts/test-guard.sh           # 가드가 실제로 죽는지 음성 대조
```

가드는 플랫폼의 `tier_verify.py` 를 **흉내내지 않는다**. 그쪽은 빌드 시점에 산출물을 보고,
이쪽은 발행 시점에 실제로 여기 놓인 파일을 본다. 두 시점 사이에 사람이 파일을 손으로
복사해 넣을 수 있고 그게 이 저장소의 실제 위험이다. 그래서 일부러 **독립적이고 거칠게** 본다 —
정밀 판정을 두 곳에 두면 갈라지고, 갈라지면 둘 다 못 믿는다.

가드가 보는 것: 질량(마스터 통째 반입) · 저작권 마커 · 잔존 `JANUS-TIER` 센티넬 ·
데이터 확장자 · 시크릿 · (실물 배치표라면) 워터마크·A4·A6·A7 필수 표식.

`test-guard.sh` 는 위반을 **임시 사본에 심어** 가드가 비-0 으로 죽는지 확인하고,
마지막에 위반을 치우면 다시 통과하는지도 본다 — "항상 죽는 가드"는 가드가 아니다.

## 경로 규약

`/baechi/` 는 **접합계약 C4 로 동결된 경로**다(URL 불변). 배치표 산출물이 바뀌어도 주소는 그대로다.

호스트(apex 하위 경로냐 별도 호스트냐)는 **N48 미결**이지만, 이 구조는 어느 쪽이든 그대로 쓴다 —
Pages 프로젝트에 어떤 도메인을 붙이든 `/baechi/` 는 그 아래에 있다.

## 지금 상태

`public/baechi/index.html` 은 **자리표시자**다. 실물 무료 배치표는 아직 없다 —
마스터에 `JANUS-TIER` 센티넬 태깅이 되어야 티어 빌드가 상위 티어 영역을 제거할 수 있고,
그 태깅은 배치표 독립 트랙 몫이다. 그때까지 주소만 잡아 둔다.

배포 절차는 `DEPLOY.md`.
